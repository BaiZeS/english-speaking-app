# 英语口语助手 · 项目功能报告

**产品名称**：English Speaking Assistant（情境化英语口语练习 App）
**当前版本**：v2.2.1（Android + 云端服务；代码已就绪、**尚未发布**——生产 OTA 此刻下发 v2.2.0（非强更），见 docs/operations.md 第 3、5 节）
**一句话定位**：用真实场景（点单、开会、汇报、谈判、面试）练口语——AI 扮演对话方，逐词评分发音，练习数据自动生成能力画像，进步看得见。

---

## 一、核心功能

### 1. 情景实战课（核心玩法，约 8–12 分钟/课）
- 8 门人工精编情景课，覆盖日常交流、职场商务、考试面试、旅行出国四大场景（如「咖啡店点单」「英文项目汇报」「协商交付日期」）。
- 三步闭环：**打基础**（跟读/复述/翻译/造句四题型）→ **任务实战**（AI 扮演客户/老板/面试官，屏幕挂任务清单，逐项打勾通关，卡壳可「要提示」）→ **复盘报告**（总分 + 发音/语法/词汇/流利度四维 + 亮点句与改进建议）。
- **打基础每一步答完立刻给完整反馈**（v2.2.0）：总分 + 五维子分（无证据的维度**不画**，不当 0 分）+ 逐词芯片含音标 + 引擎实际听到的转写 + 中文建议；≥85 分停留 5 秒自动进下一题，**滚动或点按即取消**，85 分以下必须自己读完再点「继续」；不及格那一步可以直接「再试一次」。中途退出/崩溃重启后，已答题的反馈仍在。
- **复盘报告不再需要等 AI**（v2.2.0）：收工请求只做确定性聚合（分数/四维/任务清单/逐句对照），亚秒级返回并**当场落库**；那两句 AI 评语由后台作业补，客户端进复盘页后轮询填充（页面先显示数字 + 「AI 正在写总评…」）。旧行为是把总评 LLM 挂在收工请求里，生产实测烧 68 秒后被手机 30 秒超时掐断——**报告写进了库而学员永远看不到**，并连出 4 个 409。
- **练完的报告随时回得去**（v2.2.0）：课程详情页「查看上次复盘」+ 首页「最近复盘」直达复盘页；同一屏上的主按钮在这种场合标成「再练一次（新开一局）」，两颗键不会混。修复前这里找不到已完成的会话，学员想复看只会**新开一局并丢掉那份报告**。
- 会话状态机支持崩溃/切后台后一键续练。

### 2. AI 生成专属课
- 输入一句真实需求（如「下周主持项目进度会」），后端两级生成（大纲→剧本），几分钟产出一门仅本人可见的定制课，可反复练、可删除。

### 3. CEFR 能力测评
- 约 5 分钟、7 题（含录音跟读——**长按**作答，且 v2.2.0 起这一页**有了录音条**：此前它根本没有电平/波形，用户看不出还在不在录），给出 A1–C2 定级 + 四维雷达；定级锁入能力画像，随练习逐步校准。
- **超时不卡死、不 500**：判级是一次 7 题的批量调用，硬预算 20s；超时就诚实返回"未定级"（雷达留空、画像零写入），而不是把学员留在原地。

### 4. 能力画像与成长轨迹
- 每次跟读/实战/测评自动更新画像（EWMA 算法），「我的」页展示雷达图 + 近 7/30/90 天趋势曲线。
- 未配置 AI 凭据时的占位数据**不计入画像**，保证图表诚实。

### 5. 经典练课四模式（多本书：商务英语、新概念一/二册）
- **跟读**：逐句评分，≥60 过关（**长按**录音 · 松开提交）；
- **影子跟读**：整篇连播 + 全程录音（**点按**开始/结束 + 已录计时，整段没有秒数上限），按句切片逐句评分，可回放对比「听我的」；
- **角色对话**：A 角播音频、B 角你来读（**长按**录音）；
- **自由对话**：9 个话题，AI 聊天 + 真实语音听写 + 评分（**点按**开始/结束，30 秒到点自动发送并提前告警）。
- 多书数据完全隔离（进度、历史、路由按书独立）。
- 练完那一屏的**总分页现在能活过进程回收**（v2.2.0）：聚合结果落一份 JSON 在应用私有目录，被系统杀掉后重开仍在。此前它在进程死亡时是**唯一**会整屏丢数据的评分面（刻意不用 Room：`5556851` 清掉的 Room 表面不复活，且已核实无法从后端重建——历史表每行没有逐词分、建议、角色名，也没有会话 id）。

### 6. 发音评测与语音合成
- 讯飞 ISE 逐词音素级评分 + 讯飞 IAT 英文听写（识别用户实际说了什么）；
- MiMo TTS 标准发音示范，多发音人可选（美音/英音）。
- 评分结果每词按分数染色高亮，强弱一目了然。
- **两种录音手势按取句长短分派**（v2.2.0）：短句面一律**按住说话 · 松开发送**（打基础 / 实战对话 / 跟读练课 / 角色对话 / 弱词本 / 测评朗读题），长录音面保留**点按开始 · 点按结束**并配**实时 `mm:ss` 计时**与到点告警（影子跟读整段无上限；自由对话 30 秒自动发送）——每一屏的文案都与它实际的手势一致。
- **录音时是一组实时声量脉冲**（v2.2.1 取代 v2.2.0 的滚动波形）：五根中心高两端低的条随当前音量跳动（数据源为 VU 包络电平，快起慢落）；松手后整组**定格在峰值**直到评分返回。滚动历史与原始逐帧峰值缓冲已删除。自由对话与测评页的录音条（v2.2.0 补齐）如今同样吃这条脉冲。

### 7. 词汇体系
- **弱词专项训练**：评分 <70 的词自动入本，听示范→跟读单词（**长按**念这个词 · 松开提交）→≥85 自动毕业；
- **表达库**：对话中一键「让这句更地道」（原句 vs 地道说法对照），金句 ⭐ 收藏，离线可翻阅。润色走 10s 硬预算，**没结果就直说「未做润色」**——它没有可靠的确定性降级可言（规则改写容易改错意思），所以宁可不做也不编一句给你。

### 8. 数据与打卡
- 首页「今日推荐」自动挑最弱维度的课；总练习量/平均分/最高分/连续天数/14 天趋势一屏可见；练习历史按书·课人读标题展示。
- 首页另有「最近复盘」：最近一场**打完**的练习的完整复盘报告，一键直达（v2.2.0）。

### 9. 应用自更新（OTA）
- App 启动自动检查新版本，应用内下载安装；更新包走服务器自托管加速通道，无需手动装包。
- 升级提示默认可「稍后再说」；只有服务器显式配置最低支持版本才进入**不可跳过**分支。**v2.2.0 就是这种一次**：收工接口从 200 改 202 且移除 `report` 字段（刻意不为旧包做兼容），所以随本版发布会把最低支持版本设为 2.2.0，旧包收到的是强更提示而非"待会儿再说"。

## 二、产品形态

- **App 信息架构**：首页 / 课程 / 词汇 / 我的 四个 Tab。
- **典型用户循环**：测评定级 → 选场景 → 打基础 → 实战通关 → 复盘 → 画像更新 → 明天推荐更弱的；想复看历史某场 → 课程详情「查看上次复盘」/ 首页「最近复盘」。
- **数据归属**：练习历史、画像、表达库、生成课按设备号存于服务端，换机填设备号即可接档；录音仅用于评分后即删，不留存语音文件。

## 三、技术栈（简述）

| 层 | 技术 |
|---|---|
| 客户端 | Kotlin + Jetpack Compose + Hilt + Room，Android 真机直连生产后端 |
| 后端 | Python FastAPI + PostgreSQL，REST API |
| AI 服务 | MiMo TTS（合成）· 讯飞 ISE/IAT（评分/听写）· 通义千问 LLM（对话/判分/生成课/测评） |
| 交付 | GitHub Actions 双 CI（后端 + APK 构建），tag 触发自动发版；Android CI 多一道 **`release-gate`**：改 `app/src/main/**` 却没在同范围 bump `versionCode` + 写 CHANGELOG 直接红，且挡住产物构建（本版把"改好了但没发到手机上"这类交付事故变成机器检查，见 CHANGELOG v2.2.0）|

## 四、质量与现状

- 后端 **573** 项自动化测试 + Android **318** 项 JVM 单测（实测；开工基线 328，旧口径 327 已过期；更早"168 项"的口径止于 v2.0.0，已在 `android/README.md` 校正），双 CI 全绿；后端 `ruff check` / `ruff format --check` / `mypy` 干净、整轮覆盖率约 90%（CI 门 85%）；数据库迁移链在 SQLite / PostgreSQL 双向上可逆，**v2.2.0 零迁移**。
- **真机验收欠着两版**（已按 2026-09-12 实测对账）：v2.2.0 **已发布**——tag 已打、`publish_apk.sh` 已自托管，OTA 通道实测返回 `latest_version=2.2.0` / `min_supported_version=0.0.0`（**非强更**）；但它的**真机验收仍然挂着**——五个症状的修复、两种手势的实际手感只有源码与单测/集成测试作证据，装机逐条走查还挂着（脚本见发布计划 §5.3）。**v2.2.1 代码已就绪、尚未打 tag / 未发布**（样式补丁：实时声量脉冲条 + 评分反馈卡中性化，非强更、后端零改动），其脉冲条手感与反馈卡观感目前同样只有源码 + 318 项 JVM 单测作证据。这一段是本报告里最重要的"未完成的现状"，别把 v2.2.1 的描述读成功能已上线。
- **同步链路有显式时延契约**（v2.2.0）：每条挂在 HTTP 请求里的大模型调用都有硬预算，规则是 `budget ≤ 30s − 同请求其它 await − 5s 余量`，最坏求和表见 `docs/operations.md` 第 5.5 节并由 `backend/tests/test_latency_budget.py` 钉死（含"新增调用点不写预算就直接红"的静态锁）。**明知还剩一行装不下**并已记在案：音频作答的 `/step` 若讯飞 IAT 挂死最坏 33s——成因是那一处 IAT 调用点没包预算（讯飞侧的活），不是 LLM 预算问题，测试里给它钉了 33s 天花板只许变小。
- 全链路降级设计：任一 AI 凭据缺失时功能仍可跑通，界面明确标注「占位分/占位音频」，不产生误导数据。诚实到底的一层（v2.2.0）：**没有证据的维度一律留空并写明原因**，总分空是"这场没有可信评分证据"而不是"你考了零分"；后台总评作业的 LLM **常常**仍会因额度/慢链路落到离线确定性文案——本版换来的是"在预算内落地"，不是"每次都有 AI 评语"。
