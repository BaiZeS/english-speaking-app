# 英语口语助手 · 项目功能报告

**产品名称**：English Speaking Assistant（情境化英语口语练习 App）
**当前版本**：v2.2.4（Android + 云端服务；**已发布并已上线 OTA** — tag `v2.2.4`、versionCode 13，生产 `/app/version` 实测返回 `latest_version=2.2.4` / `min_supported_version=2.2.0` / `source=env`，即对 2.2.0 及以上仍为**非强更**（可「稍后再说」），只有低于 2.2.0 的旧包是不可跳过分支。口径与逐版上线实录见 docs/operations.md 第 3、5 节）
**一句话定位**：用真实场景（点单、开会、汇报、谈判、面试）练口语——AI 扮演对话方，逐词评分发音，练习数据自动生成能力画像，进步看得见。

## 一、核心功能

### 1. 情景实战课（核心玩法，约 8–12 分钟/课）
- 8 门人工精编情景课，覆盖日常交流、职场商务、考试面试、旅行出国四大场景（如「咖啡店点单」「英文项目汇报」「协商交付日期」）。
- 三步闭环：**打基础**（跟读/复述/翻译/造句四题型）→ **任务实战**（AI 扮演客户/老板/面试官，屏幕挂任务清单，逐项打勾通关，卡壳可「要提示」）→ **复盘报告**（总分 + 发音/语法/词汇/流利度四维 + 亮点句与改进建议）。
- **打基础每一步答完立刻给完整反馈**（v2.2.0）：总分 + 五维子分（无证据的维度**不画**，不当 0 分）+ 逐词芯片含音标 + 引擎实际听到的转写 + 中文建议；≥85 分停留 5 秒自动进下一题，**滚动或点按即取消**，85 分以下必须自己读完再点「继续」；不及格那一步可以直接「再试一次」。中途退出/崩溃重启后，已答题的反馈仍在。
- **复盘报告不再需要等 AI**（v2.2.0）：收工请求只做确定性聚合（分数/四维/任务清单/逐句对照），亚秒级返回并**当场落库**；那两句 AI 评语由后台作业补，客户端进复盘页后轮询填充（页面先显示数字 + 「AI 正在写总评…」）。旧行为是把总评 LLM 挂在收工请求里，生产实测烧 68 秒后被手机 30 秒超时掐断——**报告写进了库而学员永远看不到**，并连出 4 个 409。
- **练完的报告随时回得去**（v2.2.0）：课程详情页「查看上次复盘」+ 首页「最近复盘」直达复盘页；同一屏上的主按钮在这种场合标成「再练一次（新开一局）」，两颗键不会混。修复前这里找不到已完成的会话，学员想复看只会**新开一局并丢掉那份报告**。
- 会话状态机支持崩溃/切后台后一键续练。

### 2. AI 生成专属课
- 输入一句真实需求（如「下周主持项目进度会」），后端两级生成（大纲→剧本），几分钟产出一门仅本人可见的定制课，可反复练、可删除。

### 3. CEFR 能力测评
- 约 5 分钟、7 题（含录音跟读——**长按**作答，且 v2.2.0 起这一页**有了录音条**：此前它根本没有电平/波形，用户看不出还在不在录），给出 A1–C2 定级 + 四维雷达；定级锁入能力画像，随练习逐步校准。
- **判级已移出请求，学员不用干等**（v2.2.2）：交卷立即返回「判级中」，后台作业用 **120s** 墙钟慢慢判，客户端每 3s（退避到 9s）轮询、上限 150s；超时也不报错，诚实告知「判级仍在后台，可在『我的-能力画像』查看」。**根因是生产实锤**：判级那次大模型调用受免费额度限速，两次都在旧的 20s 同步硬预算处撞墙，落到只带真实发音分的空态，又被幂等回放固化——学员看到的症状是"测评完只有发音一维有分"。
- **"重新判级"翻案入口**（v2.2.2）：stub 结果（含本版之前已被固化的存量测评）在结果页一键**重判，不需要重做题**；判级结果就位后四维雷达 + CEFR 徽章补齐，且画像**只写一次**（后台作业走条件写回，并发双跑输家整事务回滚——防分数与事件双计）。
- **两级超时必须成对放宽**（v2.2.2 的二阶根因，已入契约）：只把墙钟放宽到 120s 而 openai SDK 的**单次 socket 超时**仍按基座 20s，先到的那个直接把作业砍死（部署后第一发冒烟 24s 仍落 stub，日志 `LLM 调用失败: Request timed out.`）；补 `ASSESSMENT_JUDGE_JOB_TIMEOUT_S=100`（介于同步 20s 与墙钟 120s 之间）才真正接住。**同步路径缺省不动**：老客户端不传 `async_judge` 就是既有 20s 预算、30s 契约零变化，两端各自向后兼容。
- **验证边界（诚实）**：判级链路的证据分两段——服务端侧已在**生产实跑留证**（异步交卷 202 → 后台 43s 慢回复被完整接住 → 轮询到终态 `source=llm`、三维有分、CEFR 落级、重判补写事件恰好 3 条无重复）；**客户端侧至今只有 curl 直连后端的证据 + JVM 单测**，真机上"交卷→等→四维全亮"与"重新判级"按钮的完整走查**尚未执行**。

### 4. 能力画像与成长轨迹
- 每次跟读/实战/测评自动更新画像（EWMA 算法），「我的」页展示雷达图 + 近 7/30/90 天趋势曲线。
- 未配置 AI 凭据时的占位数据**不计入画像**，保证图表诚实。
- **画像与统计每次恢复可见都重拉**（v2.2.3）：底部 Tab 切换走返回栈 `saveState/restoreState`、ViewModel 不重建，而「我的」/「首页」/「词汇」三屏此前只在**首次进入**时拉一次——症状是"完成测评后回到『我的』看不到四维能力维度"（看到的确是测评前快照），同 bug 类还包括首页「未测评引导」卡不消失、做完弱词训练回词汇 Tab 弱词数不降。本版起三屏恢复可见即刷新（测评返回 / 切回本 Tab / App 回前台全覆盖），刷新期间旧数据保留不闪烁。
- **画像兜底位的取值门**（v2.2.3 收紧）：画像里有**真证据**的维度才允许在测评结果页补位，不再被「已测评但四维全空」这种不可达状态污染；判级未完成而日常练习已攒够该维证据时补位并标注「来自日常练习画像，仅供参考」，无证据的维度仍诚实留空。

### 5. 经典练课四模式（多本书：商务英语、新概念一/二册）
- **跟读**：逐句评分，≥60 过关（**长按**录音 · 松开提交）；
- **影子跟读**：整篇连播 + 全程录音（**点按**开始/结束 + 已录计时，整段没有秒数上限），按句切片逐句评分，可回放对比「听我的」；
- **角色对话**：A 角播音频、B 角你来读（**长按**录音）；
- **自由对话**：9 个话题，AI 聊天 + 真实语音听写 + 评分（**点按**开始/结束，30 秒到点自动发送并提前告警）。
- 多书数据完全隔离（进度、历史、路由按书独立）。
- 练完那一屏的**总分页现在能活过进程回收**（v2.2.0）：聚合结果落一份 JSON 在应用私有目录，被系统杀掉后重开仍在。此前它在进程死亡时是**唯一**会整屏丢数据的评分面（刻意不用 Room：`5556851` 清掉的 Room 表面不复活，且已核实无法从后端重建——历史表每行没有逐词分、建议、角色名，也没有会话 id）。

### 6. 发音评测与语音合成
- 讯飞 ISE 逐词音素级评分 + 讯飞 IAT 英文听写（识别用户实际说了什么）；
- MiMo TTS 标准发音示范，多发音人可选（美音/英音）。
- 评分结果每词按分数染色高亮，强弱一目了然。
- **两种录音手势按取句长短分派**（v2.2.0）：短句面一律**按住说话 · 松开发送**（打基础 / 实战对话 / 跟读练课 / 角色对话 / 弱词本 / 测评朗读题），长录音面保留**点按开始 · 点按结束**并配**实时 `mm:ss` 计时**与到点告警（影子跟读整段无上限；自由对话 30 秒自动发送）——每一屏的文案都与它实际的手势一致。
- **录音时是一组实时声量脉冲**（v2.2.1 取代 v2.2.0 的滚动波形）：五根中心高两端低的条随当前音量跳动（数据源为 VU 包络电平，快起慢落）；松手后整组**定格在峰值**直到评分返回。滚动历史与原始逐帧峰值缓冲已删除。自由对话与测评页的录音条（v2.2.0 补齐）如今同样吃这条脉冲。

### 7. 词汇体系
- **弱词专项训练**：评分 <70 的词自动入本，听示范→跟读单词（**长按**念这个词 · 松开提交）→≥85 自动毕业；
- **表达库**：对话中一键「让这句更地道」（原句 vs 地道说法对照），金句 ⭐ 收藏，离线可翻阅。润色走 10s 硬预算，**没结果就直说「未做润色」**——它没有可靠的确定性降级可言（规则改写容易改错意思），所以宁可不做也不编一句给你。

### 8. 数据与打卡
- 首页「今日推荐」自动挑最弱维度的课；总练习量/平均分/最高分/连续天数/14 天趋势一屏可见；练习历史按书·课人读标题展示。
- 首页另有「最近复盘」：最近一场**打完**的练习的完整复盘报告，一键直达（v2.2.0）。

### 9. 应用自更新（OTA）
- App 启动自动检查新版本，应用内下载安装；更新包走服务器自托管加速通道，无需手动装包。
- 升级提示默认可「稍后再说」；只有服务器显式配置最低支持版本才进入**不可跳过**分支。**v2.2.0 就是这种一次**：收工接口从 200 改 202 且移除 `report` 字段（刻意不为旧包做兼容），所以随本版发布会把最低支持版本设为 2.2.0，旧包收到的是强更提示而非"待会儿再说"。**当前生产状态**：`APP_MIN_SUPPORTED_VERSION=2.2.0` 生效中（2026-09-28 实测 `/app/version` 即此值），故 2.2.0 及以上对 v2.2.4 仍是可推迟的更新提示。
- **检查失败不再锁死 App**（v2.2.4，动机是一条真实事故 2026-09-14~26）：生产宿主端口 5173 被同机另一项目的进程抢占、发布容器 bind 失败停在 `created`，公网 5173 上**任何路径**都返回某个系统的 HTML 首页（HTTP 200 假活）——App 拿 JSON 解析必炸。当时那批客户端把这次失败做成了困局：失败弹窗正文直接上屏原始异常文本（内嵌整段 HTML/JSON 响应体），而点「知道了」会**立刻重查再失败**、回前台 `onResume` 再中一次，模态框把用户锁死在所有页面之外——**连改服务器地址的唯一入口「设置」都进不去**。本版四处根治：关闭只关弹窗（不再发任何请求）、失败弹窗新增**「进入设置」逃生门**（栈语义与底部栏切 Tab 一致，返回键落「我的」）、失败文案固定为一句中文（残片与超长一律拒绝上屏）、回前台自动重查改**静默**（失败只记日志，冷启动与手动检查仍弹一次告知）。三个折叠/归位判定都剥成纯函数、由 JVM 行为锁钉住（11 例）。

## 二、产品形态

- **App 信息架构**：首页 / 课程 / 词汇 / 我的 四个 Tab。
- **典型用户循环**：测评定级 → 选场景 → 打基础 → 实战通关 → 复盘 → 画像更新 → 明天推荐更弱的；想复看历史某场 → 课程详情「查看上次复盘」/ 首页「最近复盘」。
- **数据归属**：练习历史、画像、表达库、生成课按设备号存于服务端，换机填设备号即可接档；录音仅用于评分后即删，不留存语音文件。

## 三、技术栈（简述）

| 层 | 技术 |
|---|---|
| 客户端 | Kotlin + Jetpack Compose + Hilt + Room，Android 真机直连生产后端 |
| 后端 | Python FastAPI + PostgreSQL，REST API |
| AI 服务 | MiMo TTS（合成）· 讯飞 ISE/IAT（评分/听写）· 通义千问 LLM（对话/判分/生成课/测评） |
| 交付 | GitHub Actions 三套工作流（后端 CI + Android CI + tag 触发自动出 APK 与 Release），发布收尾走 `publish_apk.sh` 自托管 OTA（GitHub 出口在本机仅 11-40KB/s）；Android CI 多一道 **`release-gate`**：改 `app/src/main/**` 却没在同范围 bump `versionCode` + 写 CHANGELOG 直接红，且挡住产物构建（这条门把"改好了但没发到手机上"变成机器检查，见 CHANGELOG v2.2.0；2026-09-15 另修掉该门在 `bash -eo pipefail` 下 `grep -c` 计数为 0 时**静默中止**的 bug，并把 actions 全集迁到 Node 24、`setup-android` 显式排除 Google 已停供的 `tools` 包）|

## 四、质量与现状

- 后端 **583** 项自动化测试 + Android **337** 项 JVM 单测全绿（**2026-09-28 在本机实测**：后端 583 passed/sqlite，Android 337 passed、0 failed；后端自 v2.2.2 起零代码改动。历史口径链条：168 → 573/328 → 582（v2.2.2 CHANGELOG 记录值，与同一棵树实测差 1，现以 583 为准）→ 583 与 326（v2.2.3）→ 337（v2.2.4，+11 例更新失败行为锁），双 CI 全绿；后端 `ruff check` / `ruff format --check` / `mypy` 干净、整轮覆盖率约 90%（CI 门 85%，该数系 v2.2.1 时点实测，v2.2.2 起未重测覆盖率仅重跑测试全绿）；数据库迁移链在 SQLite / PostgreSQL 双向上可逆，**v2.2.0~v2.2.4 零迁移**。
- **真机验收欠着五版**（v2.2.0/v2.2.1/v2.2.2/v2.2.3/v2.2.4 全部未做装机走查，这是本报告里最重要的"未完成的现状"）：五版客户端行为的现有证据止于「源码 + 337 项 JVM 单测 + 后端集成测试 + CI 出包 + curl 直连生产端点」，**没有任何一条被真机确认过**。v2.2.0 那批（逐条对应用户报告的 5 个症状 + E2/E3/E4/E5 + 升级提示走查）脚本还挂在发布计划 §5.3；v2.2.1 的脉冲条手感与反馈卡观感待验；v2.2.2 的"交卷→判级中→四维全亮"与「重新判级」按钮只跑过服务端 curl 链路；v2.2.3 的 Tab 刷新、v2.2.4 的失败弹窗可关闭与「进入设置」逃生门同样只有单测。发布状态倒是齐的：**v2.2.0~v2.2.4 全部已打 tag、已发布、生产 OTA 现下发 v2.2.4**（逐版上线实录见 docs/operations.md 第 5 节）。
- **一条真实交付事故（说明"发布了"和"用户拿到了"是两件事）**：v2.2.3 于 2026-09-15 走完发版动作（tag、GitHub Release、APK 落服务器 `static/apk/`、`.env` 写 `APP_LATEST_VERSION=2.2.3`），但同一时刻那次 `restart` 的容器 **bind 宿主 5173 失败、停在 `created`** ——端口已被同机另一项目（data-collection）的 node 进程占用，它对任意路径返回 HTTP 200 的 HTML（**假活**）。结果：生产 API 与 OTA 实际静默下线约 12 天（2026-09-14~26），期间学员的症状是"打开 App 就弹 JSON 报错、关不掉、进不了设置、永远更新不了"。恢复办法是给抢占者改端口（本项目 5173 是烧进 release 包的公开契约，动不得），判别与预防口径已写入 docs/operations.md 第 2 节（三步硬核验）与第 6 节第一条，完整事故时间线见该文件第 5 节 v2.2.3 条；客户端侧的困局根治即 v2.2.4。**教训**：发版收尾的验收必须是**按公网口径实测 `/app/version` 返回 JSON 且 `source=env`**，并顺带核对 `docker ps -a` 的容器状态（`Created` 也算没起来）与 5173 的持有者身份——localhost 通、容器 healthy 都不足以证明用户拿得到。
- **同步链路有显式时延契约，且作业类预算有配对规则**（v2.2.0 立约，v2.2.2 补成对放宽）：每条挂在 HTTP 请求里的大模型调用都有硬预算，规则是 `budget ≤ 30s − 同请求其它 await − 5s 余量`，最坏求和表见 `docs/operations.md` 第 5.5 节并由 `backend/tests/test_latency_budget.py` 钉死（含"新增调用点不写预算就直接红"的 AST 静态锁）。两类**故意大于 30s** 的后台作业（总评文案 45s、CEFR 判级 120s）走 202 + 轮询、不在 socket 上等，但都必须封顶，且**墙钟预算与单次 socket 超时要同扩**——只扩一边等于没扩（v2.2.2 部署后二阶根因实测：43s 的慢回复需要 120s 墙钟 + 100s socket 两个都放宽才接得住）。测试另有"作业预算必须大于同步预算""async 分支不许 await judge_level"两条看门狗。**明知还剩一行装不下**并已记在案：音频作答的 `/step` 若讯飞 IAT 挂死最坏 33s——成因是那一处 IAT 调用点没包预算（讯飞侧的活），不是 LLM 预算问题，测试里给它钉了 33s 天花板只许变小。
- 全链路降级设计：任一 AI 凭据缺失时功能仍可跑通，界面明确标注「占位分/占位音频」，不产生误导数据。诚实到底的一层（v2.2.0）：**没有证据的维度一律留空并写明原因**，总分空是"这场没有可信评分证据"而不是"你考了零分"；后台总评作业的 LLM **常常**仍会因额度/慢链路落到离线确定性文案——本版换来的是"在预算内落地"，不是"每次都有 AI 评语"。
